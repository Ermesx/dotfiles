# Conventions

## Line endings and formatting

`.editorconfig` is the authority; `.gitattributes` matches it.

- `*.ps1`, `*.ps1.tmpl`, `*.psm1`, `*.psd1`, `*.bat`, `*.cmd`: **CRLF**.
- Everything else (`*.md`, `*.yaml`, `*.json`, other `*.tmpl`): **LF**.
- Indent and other formatting rules: follow `.editorconfig`.

## Scripts

- Install scripts are a flat list rendered by the template: one command per item, no PowerShell loops, no result
  checks. The commands converge by themselves (`scoop install`, `scoop bucket add`, `Install-Module`,
  `dotnet tool install` skip or warn on what is installed); a failure shows in the output and in
  `Installed-Apps-Modules.Tests.ps1`. Add a state check only where a command would fail or prompt otherwise (the
  WSL distro, the ssh-agent service).
- User-facing progress lines use `Write-Host "► <Action>" -ForegroundColor Cyan`.

## Generated documentation

Text between `<!-- BEGIN:packages -->` / `<!-- END:packages -->` in `ReadMe.md` and between
`<!-- BEGIN:bindings -->` / `<!-- END:bindings -->` in `docs/terminal-bindings.md` is generated by the `docs-sync`
agent and overwritten on its next run. Change the source (`packages.yaml`, `home/dot_profile/*.ps1`,
`home/dot_profile/tools/*.ps1`) or the agent prompt instead of editing the region. After a Claude Code edit of a source file a hook asks the session to run the
agent; for edits made elsewhere (editor, another tool), run it yourself.

## PowerShell profile

The profile imports the modules of the selected profiles (`modules` in the view, see [packages.md](packages.md)),
then dot-sources every `~/.profile/*.ps1` by glob at apply time. A new general fragment in `home/dot_profile/`
needs no profile edit.

Code that belongs to one tool lives in `home/dot_profile/tools/[zz-]<tool>.ps1[.tmpl]`, where `<tool>` is the tool's
label in the view's `tools`. The profile template finds the fragments by globbing that folder and loads them in
file-name order, only for selected tools; `.chezmoiignore` deploys only those files. The `zz-` prefix loads a
fragment after the others and is not part of the tool name: `zz-starship.ps1` and `zz-zoxide.ps1` come last, in that
order (both hook the prompt, `zoxide` must be last). A new tool fragment needs no template edit. Fragments carry no
`Get-Command` guard: the selection guarantees the tool.
